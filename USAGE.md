# Как пользоваться BioGit

Пошаговое руководство. Рассчитано на человека, который раньше никогда
не работал с системами контроля версий — весь git-подобный механизм
спрятан внутри, терминал не нужен.

Если вы разработчик и хотите собрать проект из исходников — вам сначала
в корневой [README](README.md), потом сюда.

---

## 1. Что BioGit делает и зачем он биологу

Эксперимент — это не только файлы с данными (таблички, fasta, картинки),
но и условия, при которых они получены: температура, pH, номер партии
реактивов. Через месяц невозможно вспомнить, при каких параметрах
получилась конкретная кривая, а «финальная_версия_2_новая.csv» — плохой
способ хранить историю.

BioGit решает это так:

- вы работаете с обычной папкой на диске, как привыкли;
- в любой момент нажимаете «Сохранить снимок» — и BioGit запоминает
  **сразу всё**: содержимое всех файлов + параметры эксперимента («рецепт»);
- снимки выстраиваются в историю, к любой точке можно вернуться
  («машина времени»);
- для проверки гипотез делается ветка: вы меняете данные, не трогая
  основную линию, а потом либо сливаете удачную гипотезу обратно,
  либо выбрасываете.

Ничего не отправляется в интернет. Все данные лежат рядом с папкой
эксперимента, в скрытой подпапке `.biogit`.

## 2. Установка и запуск (Windows 10/11)

Нужно один раз поставить:

1. **Rust** — с https://rustup.rs (установщик MSVC). Если установщик
   попросит Visual Studio Build Tools — ставьте компонент
   «Desktop development with C++».
2. **Node.js не ниже 18** — с https://nodejs.org.

Затем из папки проекта:

```powershell
npm install          # один раз, скачивает зависимости интерфейса
cargo tauri dev      # запуск для работы/отладки
```

Первая компиляция долгая, 5–15 минут — это нормально, дальше сборки
инкрементальные и занимают секунды.

Когда надоест `cargo tauri dev`, соберите установщик:

```powershell
cargo tauri build    # результат в target/release/bundle/ (NSIS/MSI)
```

Приложение после этого ставится как обычная программа и запускается
из меню «Пуск».

## 3. Первый запуск

При старте BioGit показывает приветственный экран с одним полем —
**путь к папке эксперимента**.

- Папки ещё нет или она пустая — введите путь и нажмите **«Создать новый»**.
  BioGit сделает внутри неё скрытую папку `.biogit` — это и есть репозиторий.
- Папка с экспериментом уже существует (например, вы копировали
  `demo_experiment`) — введите путь и нажмите **«Открыть репозиторий»**.
  Если в ней ещё нет `.biogit`, сначала создайте репозиторий той же
  кнопкой «Создать новый» — данные при этом не трогаются.

Путь запоминается, при следующем запуске подставится сам. Сверху окна
всегда видны текущая папка и активная ветка.

Совет: не открывайте как папку эксперимента что-то вроде `C:\Users\...`
или диск целиком — снимок фиксирует все файлы папки, поэтому рабочая
папка должна содержать только один эксперимент.

---

## 4. Рабочий стол

Главный экран. Три панели сверху и полоса сохранения снизу.

**Сырьё** — список файлов рабочей папки с размерами. Всё, что видно
в этом списке, попадёт в следующий снимок. Скрытые папки (включая
`.biogit`) в список не попадают — они не часть данных.

**Рецепт** — текстовое поле с JSON параметров эксперимента. Что сюда
писать — решать вам, например:

```json
{
  "temperature": 310,
  "ph": 7.4,
  "buffer": "HEPES",
  "reactor_lot": "A-2026-114"
}
```

Рецепт сохраняется вместе со снимком и участвует в его хеше: изменение
одного числа делает снимок другим. Это гарантирует, что «тот же самый
снимок» всегда означает «те же файлы и те же условия». Поле можно
оставить пустым, если параметры не нужны.

**Результат** — карточка последнего снимка текущей ветки: короткий хеш,
сообщение, автор, число файлов. Кнопка «Вернуть это состояние» — та же
машина времени, просто под рукой.

**Полоса сохранения.** Заполните автора (запомнится) и сообщение
(что изменилось — «добавили серию с pH 6.8»), проверьте рецепт и нажмите
**«Сохранить снимок»**. Всё. Снимок появится в истории.

Важные правила:

- автор обязателен, сообщение — нет (но лучше писать);
- снимок фиксирует **все** файлы рабочей папки, «частично» не бывает;
- снимок делается на той ветке, которая выбрана сейчас.

---

## 5. История и машина времени

Экран «История» — горизонтальная лента снимков текущей ветки, новые
слева. На каждом: хеш, время, сообщение, автор, число файлов. У снимков
слияния есть метка «слияние».

- Кликните по снимку — снизу раскроется карточка с деталями и параметрами
  эксперимента (чипсами, по 8 штук).
- Кнопка **«Машина времени: вернуть файлы из этого снимка»** возвращает
  содержимое всех файлов к выбранному моменту.

Что важно знать про машину времени:

- файлы перезаписываются теми версиями, что были в снимке;
- файлы, которых в том снимке **не было**, остаются на месте — BioGit
  их не удаляет и не трогает. Так безопаснее для данных, но после
  отката папку стоит просмотреть глазами;
- откат не «переписывает историю»: сама история остаётся, а следующий
  снимок просто зафиксирует откаченное состояние как новое.

## 6. Ветви и слияние

Ветка — это способ попробовать гипотезу, не рискуя основной линией.

**Создать ветку.** На экране «Ветви и слияние» введите имя
(например, `hypothesis-low-ph`) и нажмите «Создать ветвь». Ветка
появится от текущего снимка. Правила имени: буквы, цифры, дефис,
подчёркивание, точка; без пробелов и слэшей.

**Переключиться.** Кнопка «Переключиться» у нужной ветки. Файлы в рабочей
папке заменяются файлами кончика той ветки. Снова-таки: файлы, которых
на этой ветке нет, а в папке есть — останутся лежать.

**Работа на ветке.** Обычная: меняете файлы, сохраняете снимки — они
попадают в историю этой ветки, основная ветка ничего не замечает.

**Слить.** Выберите ветку-источник в списке и нажмите **«Слить»**.
Слияние идёт в текущую ветку. BioGit сравнивает обе ветки с их общим
предком и делает по-настоящему умное слияние:

- файл менялся только в одной ветке — берётся изменённая версия;
- файл добавлен в одной ветке — добавляется;
- файл удалён в одной и не менялся в другой — удаляется;
- текст меняли в обеих ветках, но в разных местах — изменения
  объединяются (даже если строки соседние);
- CSV (`.csv`, `.tsv`) сливается по **первой колонке** — она считается
  ключом (`gene_id` в демо). Строки, добавленные/удалённые в разных
  ветках, объединяются; если одну строку правили в обеих ветках, но в
  разных колонках — сойдётся и это, по ячейкам;
- одинаковые правки с двух сторон применяются один раз.

**Конфликт** — это когда одна и та же ячейка/строка/кусок текста
изменён по-разному в обеих ветках, или файл удалён в одной ветке и
изменён в другой. Тогда слияние **отменяется целиком**, репозиторий и
рабочая папка остаются как были, а в отчёте красным перечислены все
расхождения с причинами. Что делать: разберитесь с файлами вручную
(или в одной из веток) и слейте снова.

Отчёт о слиянии зелёным показывает, что принесено. Удачное слияние
создаёт снимок с двумя родителями — оба направления истории сохраняются.

## 7. Демо-сценарий (5 минут)

1. Скопируйте папку `demo_experiment` куда-нибудь (скажем, в
   `D:\demo_experiment`) и откройте её в BioGit («Создать новый»,
   чтобы появился `.biogit`).
2. **Рабочий стол**: посмотрите JSON в «Рецепте» → автор, например
   `Дмитрий`, сообщение «Начальные данные» → «Сохранить снимок».
3. **Ветви и слияние**: создайте ветку `hypothesis-low-ph`.
4. Вернитесь на **Рабочий стол** (вы теперь на `main`), в
   `expression.csv` измените значение `p_value` у строки `TP53`
   и сохраните снимок «main: правка TP53».
5. **Ветви и слияние**: переключитесь на `hypothesis-low-ph`. Файлы
   откатились к снимку-основе. Теперь в `expression.csv` измените
   **другую** строку — например, добавьте новый ген `MYC` — и сохраните
   снимок «гипотеза: +MYC».
6. Переключитесь на `main`, выберите источник `hypothesis-low-ph`,
   нажмите **«Слить»**. В отчёте должно быть «Слияние выполнено»,
   а в итоговом CSV — и правка с `main`, и `MYC` с ветки.
7. **История**: щёлкните любой снимок и нажмите «Машина времени» —
   файлы вернутся к тому моменту. Потом верните последний, если хотите.

## 8. Что лежит на диске

Всё хозяйство — в скрытой папке внутри эксперимента:

```
.biogit/
├── HEAD               # имя текущей ветки (текст, например "main")
├── refs/heads/        # по файлу на ветку, внутри — хеш последнего снимка
└── objects/           # все данные, сжатые gzip
    └── ab/cdef...     # имя объекта = sha256 его содержимого
```

Полезно знать:

- одинаковые файлы хранятся один раз — повторный снимок без изменений
  почти ничего не добавляет;
- объекты нельзя править руками: хеш снимка пересчитывается при каждом
  чтении, и подделка будет обнаружена;
- скопировать эксперимент = скопировать всю папку вместе с `.biogit`.

## 9. Типичные вопросы и проблемы

**После переключения ветки в папке остались «лишние» файлы.**
Так и задумано: BioGit перезаписывает файлы из снимка, но не удаляет то,
чего в снимке нет. Лишнее уберите руками (или снимите как есть — тогда
это станет частью истории ветки).

**«Дубликат ключа в колонке gene_id».** CSV-слияние требует, чтобы
ключевая (первая) колонка была уникальной. Уберите дубликаты и повторите.

**`EBUSY: resource busy or locked, watch '...target...'` при запуске dev.**
Vite пытался следить за папкой, куда пишет Cargo. Правильный конфиг уже
в репозитории (`server.watch.ignored` в `vite.config.ts`) — не убирайте
оттуда записи про `target` и `src-tauri`.

**`icons/icon.ico not found` при сборке.** Иконки лежат в
`src-tauri/icons/` — проект нужно копировать целиком. Если собираете
поверх старой сборки: `cargo clean -p biogit-app`.

**Долго компилируется.** В первый раз — да (Tauri + Polars большие).
Дальше инкрементально.

**Ошибка линковки MSVC.** Доустановите Visual Studio Build Tools
с компонентом C++.

## 10. Ограничения текущей версии

Честный список, чтобы не удивляться:

- снимок фиксирует папку целиком — понятия «проиндексировано/не
  проиндексировано» нет;
- конфликт слияния нельзя разрешить в интерфейсе — только отмена и
  правка файлов руками;
- ключ CSV-слияния жёстко первая колонка, настроить нельзя;
- у слияния в «рецепт» попадают параметры целевой ветки, параметры
  ветки-источника не сохраняются;
- история показывается по первой родительской линии, «граф» целиком
  не рисуется;
- больших репозиториев мы не ждали: дифф текста работает, пока
  произведение числа строк не превышает ~миллиона, дальше файлы
  сравниваются грубо (любая двойная правка станет конфликтом).

## 11. Для разработчиков: тесты

```powershell
cargo test -p biogit-core
```

54 проверки: упаковка ДНК и обратный комплемент, дедупликация хранилища,
целостность снимков, защита от выхода за пределы папки, валидация веток,
слияние текста и CSV (включая конфликты и откат) и полный интеграционный
цикл «снимок → ветка → слияние → откат».

# BioGit — контроль версий экспериментальных данных

![Лицензия MIT](https://img.shields.io/badge/лицензия-MIT-green)
![Стек](https://img.shields.io/badge/стек-Rust%20%2B%20Tauri%20v2%20%2B%20React-orange)

Локальная система управления версиями для биоинформатиков и биохимиков.
BioGit фиксирует **файлы + параметры эксперимента** («рецепт»), чтобы любой
результат можно было точно воспроизвести. Никакого терминала: всё управление —
через три экрана интерфейса.

| Экран | Что делает |
|---|---|
| **Рабочий стол** | Панели «Сырьё» (файлы), «Рецепт» (JSON-параметры), «Результат» + кнопка «Сохранить снимок» |
| **История** | Горизонтальный таймлайн снимков; «Машина времени» — вернуть файлы из любого снимка |
| **Ветви и слияние** | Ветви гипотез, переключение, умное слияние с отчётом (расхождения — красным) |

## Структура проекта (монорепозиторий Tauri v2)

```
biogit/
├── src/                     # Фронтенд: React + TypeScript
│   ├── App.tsx              #   каркас, вкладки, приветственный экран
│   ├── api.ts               #   типизированные вызовы invoke() к бэкенду
│   └── screens/             #   Рабочий стол / История / Ветви и слияние
├── src-tauri/               # Бэкенд: Rust + Tauri v2
│   ├── src/commands.rs      #   #[tauri::command] — обёртки над ядром
│   ├── tauri.conf.json      #   конфигурация окна и сборки
│   ├── capabilities/        #   права окна (core:default)
│   └── icons/               #   иконки (icon.ico обязателен для Windows)
├── crates/biogit-core/      # Ядро на чистом Rust (без GUI-зависимостей)
│   └── src/
│       ├── storage.rs       #   CAS-хранилище: SHA-256, gzip, дедупликация
│       ├── encoding.rs      #   2-битное кодирование A/C/G/T + маска N
│       ├── object.rs        #   Снимок и дерево файлов (JSON)
│       ├── snapshot.rs      #   Репозиторий: снимки, история, машина времени
│       ├── branch.rs        #   Ветви гипотез
│       └── merge.rs         #   Умное слияние: текст (хунки), CSV (Polars)
├── demo_experiment/         # Демо-данные для первого знакомства
├── package.json             # Фронтенд-зависимости (React, Vite, Tauri API)
└── Cargo.toml               # Rust-workspace: biogit-core + biogit-app
```

Данные каждого эксперимента хранятся в скрытой папке `.biogit/` **внутри
рабочей папки**: объекты CAS (`objects/`), ссылки веток (`refs/heads/`),
текущая ветка (`HEAD`). Скрытые папки при обходе игнорируются.

## Требования

- **Windows 10/11** (WebView2 уже входит в состав системы)
- **Rust stable** — https://rustup.rs (установщик MSVC; нужен Visual Studio
  Build Tools с «Desktop development with C++»)
- **Node.js ≥ 18** — https://nodejs.org

## Сборка и запуск

```powershell
# 1. В корне распакованной папки — установка фронтенд-зависимостей
npm install

# 2. Запуск в режиме разработки (первый раз компилирует 5–15 минут)
cargo tauri dev

# 3. Сборка установщиков (NSIS/MSI)
cargo tauri build
# результат: target/release/bundle/
```

Приложение стартует с приветственного экрана: укажите путь к папке
эксперимента и нажмите «Открыть репозиторий» или «Создать новый».

## Демо-сценарий (5 минут)

1. Скопируйте папку `demo_experiment` куда угодно (например, `D:\demo_experiment`)
   и откройте её в BioGit.
2. **Рабочий стол**: проверьте JSON в «Рецепте» → «Сохранить снимок»
   (автор: -, сообщение: «Начальные данные»).
3. **Ветви и слияние**: создайте ветвь `hypothesis-low-ph`, переключитесь
   на неё (файлы откатятся к снимку-основе), измените одну строку
   `expression.csv` (например, `p_value` у TP53) и сохраните второй снимок.
4. Переключитесь на `main`, измените **другую** строку CSV, сохраните снимок.
5. **Ветви и слияние**: выберите источник `hypothesis-low-ph` → «Слить».
   CSV объединится по ключевой колонке `gene_id`: обе правки попадут в итог.
6. **История**: нажмите на любой снимок → «Машина времени» — файлы вернутся
   к тому состоянию.

## Тесты

```powershell
cargo test -p biogit-core
```

**54 теста**: roundtrip 2-битного кодирования (`ATCGATCGNNNATCG`, маска N,
обратный комплемент через побитовый NOT), дедупликация CAS по хешу,
раскладка `objects/ab/cdef…`, целостность снимков, защита от path traversal,
валидация имён веток, слияние текста хунками (включая соседние строки),
CSV по ключевой колонке (включая поячеечное), конфликты и откат слияния,
полный интеграционный цикл «снимок → ветвь → слияние → откат».

## Устранение неполадок

- **`EBUSY: resource busy or locked, watch '…\target\debug\deps\….dll'`** —
  Vite пытался следить за каталогом `target/`, куда одновременно Cargo пишет
  библиотеки; Windows блокирует записываемые файлы, и наблюдатель падает.
  Исправление уже входит в `vite.config.ts` (блок `server.watch.ignored`).
  Если вы правите конфиг вручную — убедитесь, что в `server.watch.ignored`
  есть `"**/target/**"` и `"**/src-tauri/**"`, затем перезапустите
  `cargo tauri dev`.
- **`icons/icon.ico not found`** — не копируйте проект частями; иконки лежат
  в `src-tauri/icons/`. Если пересобираете поверх старой сборки:
  `cargo clean -p biogit-app`.
- **Долго компилируется** — нормально для первого запуска (Tauri + Polars);
  последующие сборки инкрементальны.
- **Ошибка линковки MSVC** — доустановите Visual Studio Build Tools
  (компонент C++).
- **Дубликаты ключей в CSV** — ключевая колонка (первая, `gene_id`) обязана
  быть уникальной; слияние сообщит о дубликатах и отменит операцию.

## Технические решения

- Хеш объектов — SHA-256 (`sha256:…`), файлы сжимаются gzip на лету чанками
  по 64 КБ; одинаковое содержимое хранится один раз.
- Хеш снимка считается по каноническому JSON метаданных (время, автор,
  сообщение, родители, ветка, дерево, параметры) — целостность проверяется
  при каждом чтении.
- Текстовое слияние — построчные «хунки» изменений против общего предка
  (как в git): правки разных и даже соседних строк объединяются,
  пересекающиеся разные правки дают конфликт и отменяют слияние целиком.
- CSV-слияние — по ключевой колонке через Polars; когда обе ветки меняли
  одну строку в разных колонках, выполняется поячеечное объединение.
